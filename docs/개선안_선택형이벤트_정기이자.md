# 개선안: 선택형 이벤트·정기 이자 납부 시스템

작성일: 2026-09-05  
대상 프로젝트: 여름 공모전 Unity 게임  
관련 피드백: [최종발표 피드백 (4차 피드백)](https://app.notion.com/p/3bd94f5130278018b37aebeba287e34a)

## 1. 피드백 반영 내용

기존 문서의 중간 목표금액 중심 설계를 다음과 같이 변경한다.

1. Markdown 파일은 프로젝트 루트가 아니라 `docs` 폴더에서 관리한다.
2. 이벤트 선택지는 플레이어가 고르는 행위와 별개로, 선택 결과마다 성공 확률을 가진다.
3. 중간 목표금액 시스템은 제거한다.
4. 특정 턴마다 플레이어에게 정기 이자를 청구한다.
5. 이자를 전부 갚지 못하면 미납 이자가 다음 청구액에 누적되고, 연체가 길어질수록 금액이 계속 커진다.

## 2. 현재 구조

- `EventSO`가 이벤트 내용, 긍정/부정 분류, 가중치, 스탯/시장 효과를 보유한다.
- `EventCalculator`가 이벤트를 선택하고 즉시 효과를 적용한다.
- `MarketManager.NextTurn()`에서 이벤트 발생과 시장 갱신이 처리된다.
- `EventNotificationUI`는 이벤트 내용을 보여주고 닫기만 한다.
- `EventLogEntry`는 이벤트 프로필과 발생 날짜만 저장한다.
- `PlayerManager`에는 현금과 코인만 있고 부채 및 이자 데이터는 없다.
- 최종 탈출 기준은 현재 `MarketManager.TargetAsset`의 5억이며, 현재는 현금 기준이다.

## 3. 확정 방향: 선택형 이벤트

### 3.1 진행 흐름

```text
턴 진행
  ↓
이벤트 선택
  ↓
선택지 표시 및 선택 확률 공개
  ↓
플레이어가 선택
  ↓
선택지 성공/실패 확률 판정
  ↓
결과 효과 적용
  ↓
이벤트 결과와 선택 내용 기록
```

### 3.2 선택 확률의 의미

플레이어가 선택지를 누르는 행위 자체는 100% 성공한다. 여기서 말하는 선택지 확률은 플레이어가 선택한 행동이 원하는 결과를 낼 확률이다.

예시:

```text
당국 조사

조사에 협조한다       성공 확률 90%
조사를 방해한다       성공 확률 55%
변호사를 고용한다     성공 확률 80%
```

선택 후에는 한 번만 확률을 판정한다. 성공하면 성공 효과를, 실패하면 실패 효과를 적용한다.

### 3.3 선택지 데이터

기존 `EventSO`에 선택지 목록을 추가한다. 선택지 하나는 다음 정보를 가진다.

- 선택지 제목
- 선택지 설명
- 성공 확률
- 선택 비용
- 성공 시 효과
- 실패 시 효과
- 성공 시 현금/부채 변화
- 실패 시 현금/부채 변화
- Support/Growth/Doubt 변화
- Supply 및 가격 변화
- 후속 이벤트 또는 추가 위험

선택 확률은 기본 확률과 상태 보정값으로 계산한다.

```text
최종 성공 확률
= 기본 성공 확률
  + 스킬 보정
  + 직업 보정
  - 현재 Doubt 또는 연체 패널티
```

확률은 0~100% 범위로 제한한다.

### 3.4 UI 원칙

- 선택지마다 성공 확률을 표시한다.
- 성공 시 효과와 실패 시 효과를 구분해 보여준다.
- 선택 비용과 부채 발생 여부를 강조한다.
- 선택 전에는 게임 시간을 정지한다.
- 선택 전에는 이벤트 창을 닫을 수 없게 한다.
- 선택 후에는 결과를 보여준 뒤 창을 닫는다.
- 선택지는 한 이벤트당 2~3개를 기본으로 한다.

확률을 숨기기보다는 공개하는 방향을 권장한다. 플레이어가 확률과 비용을 비교해 판단해야 선택의 의미가 생기기 때문이다.

### 3.5 이벤트 예시

#### 당국 조사

- 조사에 협조한다: 성공 확률 90%, 현금 지출, Doubt 감소
- 조사를 방해한다: 성공 확률 55%, 성공 시 비용 절약, 실패 시 Doubt 크게 증가
- 변호사를 고용한다: 성공 확률 80%, 큰 현금 지출, 실패 위험 감소

#### 해킹 사고

- 피해자를 보상한다: 성공 확률 85%, 현금 지출, Support 증가
- 대출을 받아 보상한다: 성공 확률 75%, 부채 발생, 정기 이자 납부 시작
- 보상을 거부한다: 성공 확률 40%, 당장 비용 없음, 실패 시 가격 하락 및 Doubt 증가

#### 거래소 상장

- 상장 수수료를 낸다: 성공 확률 95%, 현금 지출, 상장 효과 안정적
- 조건을 거절한다: 성공 확률 100%, 비용 없음, 상장 기회 상실
- 무리하게 추진한다: 성공 확률 50%, 성공 시 큰 가격 상승, 실패 시 부채 또는 Doubt 증가

## 4. 제거되는 기능: 중간 목표금액

기존에 계획했던 30턴·90턴·180턴·365턴별 목표 순자산 시스템은 이번 개선안에서 제외한다.

플레이어에게 특정 금액을 달성하라고 요구하는 대신, 특정 턴에 실제로 돈을 납부하게 해 긴장감을 만든다.

최종 5억 탈출 조건은 별도 시스템으로 유지한다. 다만 부채를 도입한 뒤에는 최종 조건을 아래 중 하나로 확정해야 한다.

- 기존처럼 보유 현금 5억
- 현금 + 코인 평가액 - 부채인 순자산 5억

대출을 이용한 뒤 바로 탈출하는 악용을 막으려면 순자산 기준을 권장한다.

## 5. 확정 방향: 특정 턴 정기 이자 청구

### 5.1 기본 개념

대출이나 이벤트 선택지로 부채가 발생하면 계약에 따라 특정 턴마다 이자를 청구한다.

```text
대출 발생
  ↓
다음 이자 납부 턴 등록
  ↓
납부 턴 도달
  ↓
이자 청구
  ↓
현금에서 자동 차감
  ↓
부족분은 미납 이자로 누적
```

이자는 플레이어가 원할 때 내는 선택 사항이 아니라, 정해진 턴에 자동으로 청구되는 의무 납부금으로 설계한다.

### 5.2 이자 데이터

초기 버전은 여러 대출을 합산한 단일 부채로 구현한다.

- 원금
- 현재 미납 이자
- 이자율
- 첫 납부 턴
- 납부 주기 또는 다음 납부 턴
- 연체 횟수
- 연체 이자율
- 대출 만기 턴

특정 턴을 명확하게 지정해야 하는 경우에는 `납부 턴 목록`을 사용하고, 반복 청구가 필요한 경우에는 `첫 납부 턴 + 납부 주기`를 사용한다.

### 5.3 이자 계산

권장 초기 계산식은 다음과 같다.

```text
이번 이자 = 원금 × 이자율
총 납부액 = 이번 이자 + 기존 미납 이자 + 연체료
```

권장 초기값:

- 첫 납부: 대출 발생 후 30턴
- 납부 주기: 30턴
- 기본 이자율: 3~5%
- 연체 이자율: 기본 이자율보다 높게 설정
- 만기: 120~180턴

### 5.4 납부 성공

현금이 총 납부액 이상이면 자동으로 차감한다.

```text
총 납부액 20,000
현재 현금 50,000

현금 20,000 차감
미납 이자 0으로 초기화
연체 횟수 감소 또는 유지
```

### 5.5 납부 실패와 이자 누적

현금이 부족하면 현금을 음수로 만들지 않는다. 보유 현금만 차감하고 부족한 금액은 미납 이자로 남긴다.

```text
총 납부액 20,000
현재 현금 8,000

현금 8,000 차감
미납 이자 12,000 기록
연체 횟수 +1
```

다음 납부 시에는 기존 미납 이자에 새 이자와 연체료가 더해진다.

```text
다음 총 납부액
= 새 이자
  + 기존 미납 이자
  + 연체료
```

따라서 특정 턴에 이자를 갚지 못하면 부채 부담이 계속 증가한다.

### 5.6 연체 패널티

- 미납 이자 누적
- 연체 이자율 적용
- Doubt 증가
- 긍정 이벤트 확률 감소
- 선택지 성공 확률 감소
- 추가 대출 제한
- 일정 횟수 이상 연체 시 부채 디폴트 엔딩 검토

## 6. UI 개선

### 이벤트 선택 창

- 선택지별 성공 확률
- 성공 시 효과
- 실패 시 효과
- 선택 비용
- 선택으로 발생하는 부채
- 현재 보유 현금

### 메인 화면

- 보유 현금
- 코인 평가액
- 총부채
- 미납 이자
- 다음 이자 납부액
- 다음 납부까지 남은 턴
- 연체 횟수

예시:

```text
현금          120,000
코인 평가액   250,000
부채           80,000
미납 이자       4,000

다음 납부액     8,000
납부까지        12턴
연체 횟수          1회
```

### 이자 청구 연출

납부 턴이 되면 다음 순서로 처리한다.

1. 이자 청구 알림 표시
2. 청구 금액 및 보유 현금 표시
3. 자동 차감
4. 납부 성공 또는 연체 결과 표시
5. 미납 이자와 다음 납부일 갱신

이자 청구는 플레이어가 체감할 수 있도록 알림, 효과음, 숫자 변화 연출을 넣는다.

### 이벤트 로그

이벤트 로그에는 다음 정보를 추가한다.

- 선택한 선택지
- 기본 성공 확률
- 최종 성공 확률
- 성공/실패 결과
- 지불한 현금
- 발생한 부채
- 발생한 미납 이자
- 적용된 최종 효과

## 7. 턴 처리 순서

`MarketManager.NextTurn()`의 처리 순서를 다음과 같이 정리한다.

```text
1. 턴 증가
2. 정기 이자 청구 여부 확인
3. 이자 자동 차감 또는 연체 처리
4. 시장 기본 계산
5. 시사 이벤트 선택
6. 선택지 입력 대기
7. 선택지 성공 확률 판정
8. 성공/실패 효과 적용
9. 가격 및 스탯 갱신
10. UI 갱신
11. 엔딩 조건 확인
```

이벤트 선택창이 열려 있는 동안에는 게임 시간을 정지한다. 이자 청구와 이벤트 선택이 같은 턴에 겹칠 경우에는 이자를 먼저 처리해 납부 압박을 명확히 한다.

## 8. 예상 코드 변경 범위

- `EventSO`: 선택지 목록 추가
- 신규 `EventChoiceData`: 성공 확률, 성공 효과, 실패 효과 정의
- `EventCalculator`: 이벤트 선택과 선택지 결과 판정 분리
- `MarketManager`: 선택 대기 상태 및 정기 이자 처리 순서 추가
- `EventNotificationUI`: 선택지 버튼과 결과 화면 추가
- `EventLogEntry`: 선택지, 확률, 성공/실패, 납부 정보 저장
- 신규 `DebtManager`: 원금, 미납 이자, 납부 턴, 연체 처리
- `PlayerManager`: 부채 및 현금 차감 연동
- `EventHub`: 선택지 결과, 이자 청구, 연체 알림 이벤트 추가
- `EventOverviewUI` 및 메인 UI: 부채·이자 정보 표시
- `EndingType` / `EndingCalculator`: 부채 디폴트 엔딩 검토

## 10. 테스트 항목

- 선택하기 전에는 이벤트 효과가 적용되지 않는가
- 선택지 확률이 0~100% 범위로 제한되는가
- 선택 결과는 한 번만 판정되는가
- 성공과 실패 효과가 동시에 적용되지 않는가
- 선택 결과가 이벤트 로그에 기록되는가
- 정해진 턴에 이자가 정확히 청구되는가
- 이자 청구 후 현금이 음수가 되지 않는가
- 현금 부족분이 미납 이자로 누적되는가
- 다음 이자에 미납 이자와 연체료가 포함되는가
- 연체가 선택지 성공 확률과 Doubt에 반영되는가
- 대출 및 이자 정보가 새 게임 시작 시 초기화되는가
- 부채가 있는 상태에서 최종 목표를 악용할 수 없는가
- 이자 청구와 이벤트 선택이 같은 턴에 발생해도 순서가 유지되는가

## 11. 최종 권장안

- 중간 목표금액 시스템은 제거한다.
- 특정 턴마다 정기 이자를 자동 청구한다.
- 이자는 갚지 못할수록 미납 이자와 연체료가 누적된다.
- 선택지는 플레이어가 직접 고르되, 선택 결과에는 각각 성공 확률을 둔다.
- 성공 확률은 공개하고, 스킬·직업·Doubt·연체 상태로 보정한다.
- 첫 구현은 단일 대출과 30턴 주기 이자로 단순하게 시작한다.
- 최종 5억 조건은 부채를 반영하는 순자산 기준을 우선 검토한다.
