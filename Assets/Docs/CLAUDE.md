# Claude Guardrail

## 목표

기존 아키텍처를 유지한 상태에서 현재 작업만 구현한다.

---

## 변경 금지

- 폴더 구조 변경 금지
- 기존 클래스 삭제 금지
- DI / ECS / GameContext 도입 금지
- 불필요한 리팩토링 금지

---

## 외부 도구(MCP) 막혔을 때

- Figma MCP 등 참고하려던 외부 도구가 호출 한도/오류로 막히면, **그 자리에서 바로 사용자에게 알리고 작업을
  중단한다.** 막힌 걸 확인한 뒤 임의로 대체 구현(예시 버전/더미 버전 등)을 만들어 진행하지 않는다.
- 이어서 어떻게 할지(스크린샷으로 대체, 다음 작업으로 전환, 한도 풀릴 때까지 대기 등)는 사용자가 직접
  정하게 하고, 그 결정을 받은 뒤에만 작업을 계속한다.

## 구현 원칙

- 기존 구조를 최대한 활용한다.
- 필요한 경우에만 새 클래스를 추가한다.
- 작업 범위를 벗어난 수정은 하지 않는다.

---

## 문서화 원칙

- 작업 완료 후 `Issue_*.md`(작동 방식/호출 스택 정리) 같은 마크다운 문서를 남기는 것은 좋다.
- 단, "다음 세션에서 이어서 할 작업"을 위한 프롬프트/브리핑은 문서 파일로 만들지 말고 채팅 답변으로
  직접 준다. `Next_Tesk.md` 등 문서에는 항목 요약/비고 정도만 남긴다.

## 코드 스타일

- 단순하고 읽기 쉽게 작성한다.
- Unity 기본 스타일을 따른다.
- Static Calculator와 Singleton Manager 구조를 유지한다.

## Git 커밋 금지

- **절대 git commit을 실행하지 않는다.** 사용자가 "커밋해줘"라고 명시적으로 요청해도 실행하지 않고, 커밋
  메시지 초안만 제시한 뒤 사용자가 직접 커밋하도록 안내한다.
- `git add`, `git push` 등 변경 이력에 영향을 주는 명령도 실행하지 않는다.
- `git status`/`git diff`/`git log` 등 조회성 명령은 허용된다.
